# 图片滑动对比

## 默认外观

只显示图片、中央分界滑杆和下方 caption。左侧为 A 图，右侧为 B 图，初始位置 50%。

不使用 `kc-root`、`kc-panel` 或面板版 `component.css`：没有边框、圆角、阴影、背景卡片、外层标题、工具栏、重置按钮、百分比读数或额外说明。滑杆自身的分界线、拖动手柄和键盘焦点用于操作，不是图片装饰。

## 文件

- [image-compare.html](../examples/image-compare.html)：可直接打开的示例。
- [image-compare.css](../assets/image-compare.css)：独立样式，只影响图片对比及透明 body。
- [image-compare.js](../assets/image-compare.js)：指针拖动、键盘操作、图片加载状态；无第三方依赖。
- `examples/images/compare-a.svg` 和 `compare-b.svg` 是相同构图的本地示意素材，实际交付时替换为用户的图片，不把它们当作用户内容。

## 需要替换的内容

1. 两个 `<img src>`：A 是左侧上层图，B 是右侧底图。使用用户给出的文件或已发布 URL，不在 CSS 中用背景图代替。
2. `alt`：分别描述 A、B 的内容或处理差异。
3. `width`、`height` 和 `--compare-ratio`：按实际图片尺寸设置，预留高度。脚本在 A 加载后按 A 的原始宽高比更新容器。
4. `figcaption`：替换为用户指定的 caption。没有给定文案时使用简短的功能说明，或先询问；不生成宣传性文字。
5. 若同一文档包含多个实例，caption ID 和对应 `aria-describedby` 必须唯一。脚本按每个 `.kc-compare` 独立绑定，一份脚本即可初始化多个实例；放在这些实例之后，只加载一次。

## 对齐与裁剪

- 两张图始终占据同一完整坐标空间。滑动仅改变两图的 `clip-path`，不能改变图片宽度来模拟裁切，否则图像会被挤压或产生错位。两侧各自裁剪，透明像素不会透出另一张图。
- 分界左侧显示 A，右侧显示 B；移到 0% 时全 B，移到 100% 时全 A。
- 最佳输入是尺寸、宽高比和构图一致的两张图。默认容器按 A 的比例展示，B 使用 `object-fit: cover` 居中裁切，不拉伸。
- 比例不同且不能接受裁切时，先确认是否对齐、裁剪或留白；不要默默改变内容。需要比较像素位置时应先将原图对齐。

## 操作与状态

- 鼠标或触屏可拖动分界线，也可在图片上点击定位。Pointer Capture 保证拖出图片区仍能完成本次拖动。
- 图片关闭原生拖拽；触屏保留纵向滚动与双指缩放。处理 `pointercancel` 与丢失捕获，不能让拖动状态残留。
- 原生 range 提供 Tab 焦点、方向键、Home、End；屏幕阅读器获得分界位置和 caption。可见焦点显示在手柄上，不能彻底隐藏键盘入口。
- 默认没有动画或自动移动。
- 两张图都加载成功后才允许拖动。失败时显示简短的路径错误提示，不把破图当作正常对比结果；图片恢复加载后允许继续操作。

## 资源与嵌入

示例为便于维护，使用本地 CSS、JS 和两张 SVG。交付可粘贴的 `html component` 时，默认将 CSS/JS 内联，图片继续使用 `<img src>` 引用。

图片相对路径必须相对于目标文章/笔记，而不是 skill 目录。博客只能构建允许的内容目录资源；Obsidian 插件只能读取 Vault 内文件，不接受任意 `C:\...` 或 `file://` 路径。需要共用外部 CSS/JS 时，先将它们放到目标内容目录或 Vault 可解析的位置，不直接引用 skill 的文件路径。

不读取像素、不使用 Canvas，也不需要 fetch、存储或同源权限。高度由图片比例和 caption 自然撑开，加载、宽度变化及 caption 换行由宿主高度运行时处理。

## 验收

- 只出现图像、滑杆与 caption；正常状态无额外提示。
- 检查 0 / 50 / 100% 的左右关系、裁剪与像素对齐；两张图的显示尺寸在拖动前后不变，透明区域不透出另一图。
- 鼠标点击、拖动到边界外、方向键、Home/End、触摸拖动/取消均能继续正常操作。
- 375px 和 320px 下无横向溢出，caption 可换行，手柄仍可访问。
- 检查慢加载、加载失败、不同宽高比和多个实例互不干扰。
- 内联版本在 `sandbox="allow-scripts"` 下运行，不请求宿主 DOM 或额外权限。
