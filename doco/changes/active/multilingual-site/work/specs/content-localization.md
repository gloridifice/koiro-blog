# 内容组织、译本选择与翻译声明

## Scope and current contracts

本文件是 `multilingual-site` 的目标规格，不是当前已实现契约。

变更前 Models.kt 将每个 Markdown 视为独立内容，公共字段与语言相关字段混在 TOML 头部；图片相对于 Markdown 文件解析。执行后模型位于 [Content.kt](../../../../../../src/main/kotlin/content/Content.kt)，编排及资源入口为 [KoiroCatCafe.kt](../../../../../../src/main/kotlin/KoiroCatCafe.kt)、[Image.kt](../../../../../../src/main/kotlin/htmlgen/Image.kt)。动态仅嵌入首页，项目与开发日志通过 `project` / `work` 关联。

[当前架构](../../../../../architecture.md)尚无已记录边界，当前 specs 尚无相关条目。本规格覆盖博文、开发日志、动态、项目，不增加动态详情页，也不规定自动翻译过程。

## Requirements

### C1. 内容包与语言命名

一篇内容对应一个目录，公共元数据与图片由译本共享：

```text
blogs/programming/example_post/
  meta.toml
  zh-CN.md
  en-US.md
  images/
    cover.jpg
```

- 文件夹中的语言 Markdown 是同一内容的版本，不是独立内容。
- 统一使用 `zh-CN`、`en-US` 等语言标识。语言从文件名推导，不在元数据重复保存。
- 内容文件夹使用语义明确的英文 `snake_case`，迁移时初始文件夹名与 `meta.toml.id` 一致，例如 `kotlin_static_blog`。语言文件名仍使用 zh-CN.md、en-US.md，不适用 snake_case。具体映射及资源处理见 [迁移规格](data-migration.md)。分类父目录按迁移映射统一为小写 snake_case。内容类型由 blogs、devlogs、actives、portfolio 顶层目录 确定，不增加冗余的内容类型字段。
- 允许只有中文文件，不要求英文或其他语言文件存在。回退不创建伪造的翻译源文件。
- 图片留在内容包中，可放在根部或子目录。译本可以引用共享图片，也可以引用自身专用图片；相对路径以该 Markdown 所在目录解析。

### C2. 公共元数据

`meta.toml` 存储不随译本改变的信息：

| 字段 | 适用范围与语义 |
|---|---|
| `id` | 各类型的稳定内容标识，用于译本关联和地址；不从翻译标题生成 |
| `published` | 整篇内容的发布总开关 |
| `date` | 有发布日期的内容使用原始发布日期，统一参与排序；项目已有展示日期的语义另行确认 |
| `class` | 博文分类标识；显示名称可由字典翻译 |
| `tags` | 博文标签标识；技术名称可原样显示 |
| `icon` / `emoji` | 博文共享图标，保留现有优先级语义 |
| `work` / `index` | 开发日志关联的项目稳定标识和日志序号 |
| `preview` | 开发日志或项目的默认封面相对路径 |
| `project` | 项目的稳定关联标识，不随展示名称翻译 |
| `url` / `status` / `type` / `lite` | 项目已有的公共属性；`type` 表示项目类型，不是内容包类型 |

字段按内容类型使用，不强迫动态或项目填写博文专属字段。`id` 满足 `[a-z][a-z0-9]*(?:_[a-z0-9]+)*`，拒绝 Windows 设备保留名，在同一内容类型内全局唯一；类型与 ID 共同标识内容。目录改名不得重算 ID。迁移映射必须显式审阅，不能用运行时翻译结果生成地址。

公共 `id`、`published` 必填；博文还要求 `date`、`class`，开发日志要求 `date`、`work`、`index`，动态要求 `date`，项目要求 `project`、`url`、`preview`、`status`、`type`、`lite`。博文 `tags` 默认空列表，`icon` / `emoji` 可省略；开发日志 `preview` 可省略。项目已有的 `date` 如 `2024-now` 原样保留为展示字符串，不按时间线日期解析。未识别的历史元数据须保留并警告，不静默丢弃。

标题、目录名称变化不得自动改变已分配的 `id`。项目名称的翻译不得破坏 `work` / `project` 关联。

### C3. 译本元数据

各语言 Markdown 保留 fenced TOML 头部，只存储本语言的信息：

| 字段 | 语义 |
|---|---|
| `title` | 本语言标题，动态无需标题 |
| `summary` | 博文摘要，替代当前实际上表示摘要的 `slug` |
| `description` | 项目的本语言简介 |
| `published` | 本译本是否可用，省略时为 `true` |
| `ai-translation` | 本译本是否由 AI 翻译，布尔值，省略时为 `false` |
| `preview` | 可选的译本封面覆盖，省略时使用公共封面 |

正文和图片说明留在 Markdown 中。`ai-translation` 不放入公共元数据，不推断其他译本的状态，不表示 AI 创作，也不自动判断是否经过人工审校。

不存储可推导的语言列表、回退状态或译本关联路径。

### C4. 发布与选择

- `meta.toml` 的 `published = false` 时，整篇内容不进入任何语言的页面、列表或 RSS。
- 整篇内容发布时，zh-CN.md 必须存在且其译本可用；否则构建失败，并指出对应内容包。
- 译本缺失或自身 `published = false` 时，均不可用于显示或回退。
- 对每个目标语言，按去重后的顺序选择：目标语言、`en-US`、`zh-CN`。
- 标题、摘要、正文、图片说明、译本封面覆盖和 AI 标记来自同一个选中译本，不能逐字段混用不同语言。公共元数据不随回退改变。
- 列表与时间线每篇内容只计一次，使用公共日期排序，不因新增译本而重复收录或变成新发布内容。
- 选择和校验在构建时完成。发布后的页面无需浏览器再次判断正文回退。

输出位置和页面语言边界见 [路由与输出规格](localized-output.md)。

### C5. 缺译与 AI 翻译提示

发生回退时，目标语言页面须说明：该内容暂无目标语言版本，以及当前显示的实际语言。界面文案使用目标语言字典，缺键时按 [页面字典规格](page-messages.md) 回退中文。

实际译本的 `ai-translation = true` 时，标明 AI 自动翻译和实际目标语言。为 `false` 或省略时，不显示 AI 翻译标记，也不得据此宣称译本一定由人工翻译。

提示复用侧边栏 Languages 空心描边 SVG，不使用徽章底色、边框或提示框。

| 位置 | AI 翻译 | 缺少目标译本 |
|---|---|---|
| 首页文章卡片（博文、开发日志） | 卡片右下角显示一个弱色翻译图标 | 同一位置显示黄色翻译图标 |
| 首页动态 | 正文末尾正常一行：弱灰色图标及文字“本动态由 AI 自动翻译为 xx 语。” | 正文末尾正常一行：黄色图标及同色文字“本动态无 xx 语，自动回退到 yy 语” |
| 文章详情 | `page_description` 整个标题信息框外、下方左侧，弱灰色图标及文字“本文章由 AI 自动翻译为 xx 语。” | 同一位置，黄色图标及同色文字“本文章无 xx 语，自动回退到 yy 语” |
| 项目展示 | 简介末尾使用同样的弱灰色行，主语为“本项目简介” | 同一位置使用同样的黄色行，主语为“本项目简介” |
| RSS | 摘要注明 AI 翻译状态 | 摘要注明缺译及实际语言 |

- 已确认颜色：AI 翻译图标与文字均使用弱灰色 `--text-color-2`（当前深色主题为 `#6e6c6c`）；缺译回退图标与整行文字统一使用黄色 `#c5a35b`，不是只有图标变黄。
- 已确认位置：文章提示是 `page_description` 的后续兄弟区域，位于整个标题、分隔线及日期信息框之外，正文之前；左侧相对信息框外边缘内缩 20px。不得再插入 h1 与日期之间。
- 视觉尺寸沿用确认的预览：提示图标 16 × 16px，24 × 24 viewBox 的描边为 1.7；行文字 12px、行高 1.7，图标与文字 gap 为 7px。卡片图标距右侧 14px、底部 12px，为图标预留空间，不覆盖摘要。
- 行提示参与正常文档流；窄屏允许文字换行，图标不挤压正文。动态提示位于全部正文末尾，不插入代码块或图片内部。
- 卡片只显示图标，不新增常驻文字；为图标提供说明文本（title 与可访问名称），解释 AI 翻译语言或缺译回退，不能只有颜色语义。图标不得遮挡摘要、日期或分类，也不是嵌套在卡片链接内的独立语言切换按钮。
- 文案中的语言名称来自实际选中译本和当前请求语言，避免将中文拼成“中文语”；xx、yy 是占位含义，不是直接发布的文案。
- 两种状态独立计算。实现设计采用以下组合规则：卡片只用一个黄色图标，说明文本同时包含回退和 AI 翻译信息；动态和详情先显示黄色回退行，再显示弱灰色 AI 翻译行，不丢失任一状态。
- 本次采用上述简短行提示，替代此前建议的独立信息区和长免责声明；不另加原文按钮，通过语言切换器进入同一内容的中文版本。动态使用稳定 `active-<id>` 锚点，项目使用 `project-<id>` 锚点，所有语言共享同一内容排序及分页。

## Boundaries, errors and compatibility

- 本文件定义变更目标；迁移和实现的实际结果以 tasks 验证为准，不进行英文正文翻译。
- 内容迁移需要同时处理正文图片、公共封面、译本封面及旧文章链接，不能仅移动 Markdown。
- `ai-translation` 必须为布尔值，不能将字符串 `"false"` 当作有效布尔值。无效元数据应在构建期报告来源。
- ID 或目标输出路径冲突必须使构建失败，报告两个冲突来源，不静默覆盖。
- 英文缺失不是错误；中文基线缺失对已发布内容是错误。整篇草稿可缺少中文；已有元数据和译本仍做语法、字段类型、ID 和图标校验，不强制读取草稿正文资源。
- 允许中文版本显式设置 `ai-translation = true`，如实显示该版本的 AI 翻译标记，不推断其来源，也不生成自指的中文原文链接。
- 博文和开发日志的可用译本必须有非空标题；项目译本必须有非空标题和 description；summary 默认空字符串。语言 Markdown 需要合法 fenced TOML 头部，动态允许空元数据头。非法布尔值、格式错误和缺少必填字段导致构建失败。

## Acceptance scenarios

- **C-A1 共享内容身份：** 同一目录有已发布的中英文 Markdown，生成后每个语言首页只有一条该内容记录，各语言文章地址使用同一 ID。
- **C-A2 优先目标语言：** 中英文都可用，中文页面使用中文，英文页面使用英文，均没有缺译提示。
- **C-A3 英文回退：** 未来注册第三种语言且没有对应译本，中英文均可用，则该语言页面使用英文并说明缺译；即使中文是页面基础字典，也不优先选择中文正文。
- **C-A4 中文回退：** 只有可用中文原文时，英文目录仍生成该内容的完整页面，说明缺少英文、当前显示中文，不生成 en-US.md。
- **C-A5 不公开草稿译本：** 英文文件存在但 `published = false`，英文页面和 RSS 使用中文；不能泄露英文草稿的标题、摘要或正文。
- **C-A6 中文基线校验：** 整篇内容已发布但中文缺失或未发布，构建失败并指出内容包，不通过英文版绕过校验。
- **C-A7 总开关：** 公共发布开关为 false，即使译本为 true，也不出现在任何语言的页面列表和 RSS。
- **C-A8 AI 默认值：** 译本省略 `ai-translation` 时不显示 AI 标签；显式 true 时卡片右下角显示弱色翻译图标，动态末尾或详情标题信息框外下方显示弱灰色图标与同色的实际翻译语言说明。
- **C-A9 状态随实际译本：** 第三种语言回退到 AI 英文译本时同时显示缺译与 AI 提示；英文译本不可用而回退到非 AI 中文时，不残留英文的 AI 标记。
- **C-A10 身份与资源稳定：** 修改标题或移动内容文件夹但保留 ID 后，内容地址不随之变化；中英文仍能引用包内同一图片。

- **C-A11 缺译视觉：** 目标译本不存在时，卡片右下角使用黄色翻译图标；动态末尾和详情标题信息框外下方的图标及整行说明均为 `#c5a35b`，不出现带背景的提示框。AI 翻译行仍为弱灰色，不被回退行染黄。
- **C-A12 位置与可访问性：** 动态行位于全部正文之后；详情提示区域紧随完整 `page_description`，位于框外下方左侧、正文之前，不在 h1、hr 或日期之间；卡片图标有可访问名称，不覆盖卡片内容或成为嵌套按钮。

- **C-A13 包命名与冲突：** 同类型重复 ID、不合法 snake_case 或 Windows 设备保留名导致构建失败；不同分类目录不能绕过同类型唯一性检查。
- **C-A14 双状态：** 缺译且选中 AI 译本时，卡片只有一个黄色图标但可访问说明包含两种状态；动态与详情显示黄色回退行和弱灰色 AI 行。
